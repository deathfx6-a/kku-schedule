# جدولي — KKU Schedule

موقع شخصي وغير رسمي لتنظيم الجدول الأسبوعي لطالب في جامعة الملك خالد. صفحة واحدة، بدون خادم أو قاعدة بيانات؛ كل البيانات في ملفات JSON بسيطة يمكن لأي شخص تعديلها بمحرر نصوص عادي دون لمس الكود.

> ⚠️ هذا الموقع غير رسمي وليس تابعًا لجامعة الملك خالد. صُمم لأغراض تنظيمية شخصية فقط، ولا يُعتمد عليه بدلًا من الجدول الرسمي الصادر من الكلية.

---

## 1) التشغيل محليًا

المتصفحات تمنع صفحات `file://` من قراءة ملفات JSON مباشرة (قيد أمني اسمه CORS)، لذلك لا يكفي فتح `index.html` بالنقر المزدوج — لا بد من خادم محلي بسيط. اختر إحدى الطرق التالية من داخل مجلد المشروع:

```bash
# بايثون (مثبّت غالبًا على macOS/Linux، ويمكن تثبيته على ويندوز)
python3 -m http.server 8000

# أو Node.js
npx serve .

# أو امتداد "Live Server" في VS Code (زر Go Live)
```

ثم افتح `http://localhost:8000` في المتصفح.

## 2) النشر على GitHub Pages

1. ارفع محتوى المجلد إلى مستودع GitHub (المسارات في المشروع نسبية، فلا حاجة لأي إعداد إضافي).
2. من إعدادات المستودع: **Settings → Pages → Deploy from a branch**، واختر الفرع (عادة `main`) والمجلد `/ (root)`.
3. بعد دقيقة أو دقيقتين، سيكون الموقع متاحًا على رابط من نوع `https://username.github.io/repo-name/`.

## 3) خريطة الملفات

```
index.html              الصفحة والقوالب (templates) — لا تحتوي على أي بيانات جدول
assets/style.css         التنسيق والألوان والوضع الداكن
assets/app.js            المنطق فقط — لا أسماء مواد أو أوقات مكتوبة هنا إطلاقًا
icons/favicon.svg        أيقونة التبويب
data/university.json     اسم الجامعة/الكلية والعام الجامعي وإخلاء المسؤولية
data/years.json          قائمة السنوات الدراسية
data/programs.json       التخصصات
data/departments.json    الأقسام العلمية وألوانها
data/subjects.json       المواد الدراسية
data/groups.json         الشعب/المجموعات وربطها بملف الجدول الخاص بها
data/activity-types.json أنواع الأنشطة (محاضرة/معمل/تمارين...)
data/calendar.json       أحداث التقويم الأكاديمي
data/schedules/*.json    جدول كل مجموعة أسبوعًا بأسبوع
```

**القاعدة الذهبية:** كل تعديل على المحتوى (مادة، دكتور، وقت، لون...) يكون في مجلد `data/` فقط. لا حاجة لفتح `app.js` أو `index.html` أبدًا لتحديث الجدول.

## 4) وصفات تعديل شائعة

### تغيير اسم الجامعة أو الكلية

افتح `data/university.json` وعدّل الحقول مباشرة:

```json
{
  "nameAr": "جامعة الملك خالد",
  "nameEn": "King Khalid University",
  "facultyAr": "كلية الهندسة",
  "facultyEn": "College of Engineering"
}
```

### إضافة سنة دراسية جديدة

أضف عنصرًا جديدًا في `data/years.json`. إن لم يكن لديك جدول أسبوعي مفصّل لهذه السنة بعد، اجعل `hasDetailedSchedule: false` وستظهر شاشة نظرة عامة (تخصصات/مواد/تقويم) بدل الجدول الأسبوعي:

```json
{
  "id": 3,
  "titleAr": "السنة الثالثة",
  "titleEn": "Third Year",
  "descriptionAr": "التخصصات والمواد والتقويم الأكاديمي",
  "descriptionEn": "Programs, subjects and the academic calendar",
  "hasDetailedSchedule": false
}
```

### إضافة تخصص جديد

في `data/programs.json`، أضف عنصرًا واذكر السنوات التي يظهر فيها هذا التخصص عبر مصفوفة `years`:

```json
{
  "id": "mechanical-engineering",
  "titleAr": "الهندسة الميكانيكية",
  "titleEn": "Mechanical Engineering",
  "descriptionAr": "التصميم الميكانيكي والتصنيع",
  "descriptionEn": "Mechanical design and manufacturing",
  "years": [2]
}
```

### إضافة مجموعة/شعبة جديدة

في `data/groups.json`. الحقل `scheduleFile` هو اسم ملف الجدول الذي سيُقرأ من `data/schedules/`؛ يمكن لعدة مجموعات أن تشترك في نفس الملف (كما تفعل `energy-a` و`energy-b` حاليًا) أو أن يكون لكل مجموعة ملفها الخاص:

```json
{
  "id": "energy-c",
  "shortLabel": "C",
  "titleAr": "هندسة الطاقة - المجموعة C",
  "titleEn": "Energy Engineering - Group C",
  "program": "energy-engineering",
  "year": 1,
  "semester": 1,
  "scheduleFile": "schedules/energy-engineering-y1-s1-c.json"
}
```

إن أشرت إلى ملف جديد، أنشئه في `data/schedules/` بنفس بنية الملف الموجود (انظر الفقرة التالية).

### إضافة مادة جديدة

في `data/subjects.json`. حقل `department` يجب أن يطابق أحد المفاتيح في `data/departments.json` (مثل `mathematics`، `physics`...) ليأخذ المادة لونها ورقمها الصحيح تلقائيًا:

```json
{ "id": "differential-equations", "nameAr": "المعادلات التفاضلية", "nameEn": "Differential Equations", "department": "mathematics", "year": 2, "semester": 1 }
```

بعدها استخدم `"subjectId": "differential-equations"` في أي محاضرة داخل ملفات `data/schedules/`.

### إضافة أسبوع جديد لمجموعة

افتح ملف الجدول الخاص بالمجموعة، مثل `data/schedules/energy-engineering-y1-s1.json`، وأضف عنصرًا جديدًا داخل مصفوفة `weeks` الخاصة بتلك المجموعة:

```json
{
  "weekNumber": 5,
  "themeAr": "التكامل والقوانين الحرارية",
  "themeEn": "Integration and thermal laws",
  "days": [
    {
      "day": "Sunday",
      "date": "2026-09-20",
      "slots": []
    }
  ]
}
```

`day` يجب أن تكون بالإنجليزية دائمًا (Sunday…Thursday)، بينما `date` بصيغة `YYYY-MM-DD`.

### إضافة محاضرة/موعد جديد داخل يوم

داخل مصفوفة `slots` لليوم المطلوب:

```json
{
  "id": "energy-a-w5-sun-01",
  "time": "08:00-09:40",
  "subjectId": "calculus-1",
  "activityType": "lecture",
  "activityAr": "التكامل بالتعويض",
  "activityEn": "Integration by Substitution",
  "instructorAr": "د. أحمد",
  "instructorEn": "Dr. Ahmed",
  "room": "A-201",
  "department": "mathematics",
  "isCoreLecture": true
}
```

**مهم جدًا — حقل `id`:** يجب أن يكون فريدًا في كل الملف ولا يتغيّر أبدًا بعد إنشائه، لأن الموقع يستخدمه لحفظ حالة "تمت المذاكرة" في متصفحك. النمط المقترح: `<مجموعة>-w<رقم الأسبوع>-<اليوم مختصرًا>-<رقم تسلسلي>`، مثل `energy-a-w5-sun-01`. إذا غيّرت `id` محاضرة موجودة بعد أن أنجزها أحد المستخدمين، سيُعتبر إنجازها "غير محفوظ" لأن المعرّف اختلف.

**محاضرة مشتركة بين مجموعتين:** استخدم نفس المعرّف بالضبط في جدولَي المجموعتين (كما يظهر حاليًا `energy-ab-w3-tue-01` في كلا المجموعتين A وB) حتى يُحتسب التقدّم بشكل متّسق.

`activityType` يجب أن يطابق أحد المفاتيح في `data/activity-types.json` (`lecture`, `lab`, `tutorial`, `quiz`, `exam`, `break`, `other`). `isCoreLecture: true` تجعل المحاضرة تُحتسب ضمن "المحاضرات الأساسية" في شريط التقدّم والمتأخرات؛ اجعلها `false` أو احذف الحقل للأنشطة الثانوية.

### إضافة استراحة

```json
{ "id": "energy-a-w5-sun-break-1", "time": "09:40-10:00", "activityType": "break" }
```

### تغيير وقت محاضرة أو الدكتور أو القاعة

ابحث عن المحاضرة بمعرّفها (`id`) داخل ملف الجدول، وعدّل `time` أو `instructorAr`/`instructorEn` أو `room` مباشرة. لا حاجة لتغيير `id`.

### تغيير الألوان (الهوية البصرية)

الألوان الأساسية معرّفة في أعلى `assets/style.css` داخل قسم *Brand tokens*:

```css
:root {
  --primary: #0f766e;       /* اللون الأساسي (تيل) */
  --primary-dark: #115e59;  /* عند التحويم/الضغط */
  --accent: #14b8a6;        /* لمؤشر "الآن" و"الأسبوع الحالي" */
}
:root[data-theme="dark"] {
  --primary: #2dd4bf;       /* نفس المتغيرات، لكن لقيم الوضع الداكن */
}
```

غيّر قيم الألوان هذه فقط دون المساس بباقي الملف. ألوان الأقسام العلمية (رياضيات، فيزياء...) منفصلة تمامًا وتُضبط من `data/departments.json`.

### إضافة لغة واجهة جديدة

كل نصوص الواجهة (الأزرار، العناوين الثابتة، رسائل الأخطاء) مجمّعة في كائن `I18N` أعلى `assets/app.js` تحت قسم *i18n*. لإضافة لغة، انسخ كائن `ar` أو `en` بالكامل، غيّر المفتاح إلى رمز اللغة الجديدة (مثل `fr`)، وترجم القيم. أما أسماء المواد والمحاضرات فهي دائمًا ثنائية (`nameAr`/`nameEn`, `activityAr`/`activityEn`...) داخل ملفات `data/` — لإضافة لغة ثالثة للمحتوى نفسه ستحتاج لإضافة حقل مواز مثل `nameFr` لكل عنصر، ثم تعديل دالة `pick()` في `app.js` لتتعرف عليه.

## 5) التخصيص من داخل الموقع (بلا تعديل أي ملف)

يستطيع الطالب تخصيص جدوله مباشرة من المتصفح:

- **تعديل موعد:** زر القلم ✎ بجانب أي موعد يفتح نافذة لتغيير المادة، والنوع، والعنوان، والدكتور، والقاعة، واليوم، والوقت، وهل هي محاضرة أساسية تُتابَع في التقدّم.
- **الأسابيع:** في أسفل النافذة تختار الأسابيع التي يُطبَّق عليها التعديل. الموقع يتعرّف تلقائيًا على "المواعيد المماثلة" في بقية الأسابيع (نفس المادة والنوع واليوم والوقت)، فتغيّر قاعة محاضرة متكررة في كل الفصل بضغطة واحدة عبر "تحديد كل الأسابيع".
- **نقل موعد إلى يوم آخر:** غيّر حقل "اليوم"؛ يُحسب تاريخه الصحيح داخل الأسبوع تلقائيًا، ويبقى تحديد "أُنجزت" محفوظًا لأن معرّف المحاضرة لا يتغيّر.
- **إضافة موعد:** زر "إضافة موعد" في شريط التخصيص، أو زر ＋ في رأس أي يوم. يمكن اختيار "مادة جديدة…" لإنشاء مادة غير موجودة في `subjects.json`، وتظهر تلقائيًا في لوحة إنجاز المواد.
- **حذف موعد:** زر "حذف" في نافذة التعديل، ويُطبَّق على الأسابيع المختارة فقط.
- **استعادة الأصل:** زر "استعادة الأصل" داخل النافذة لموعد بعينه، أو "استعادة الجدول الأصلي" في الشريط لإلغاء كل تعديلات المجموعة.
- **النسخ الاحتياطي:** التعديلات محفوظة في متصفح الجهاز فقط (المفتاح `kkuCustomizations`)، فلا تنتقل بين الجوال والحاسب تلقائيًا. استخدم "تصدير نسخة" لتنزيل ملف JSON، ثم "استيراد نسخة" على الجهاز الآخر.

**كيف يعمل تقنيًا:** ملفات `data/` لا تُمسّ أبدًا. التعديلات تُخزَّن "فروقًا" فقط (ما تغيّر عن الأصل) وتُطبَّق فوق بيانات JSON لحظة بناء الجدول. لذلك إن حدّثتَ ملف الجدول لاحقًا ستظهر التحديثات لكل الطلاب، وتبقى تعديلات كل طالب الشخصية فوقها. وإن أعاد الطالب قيمةً إلى أصلها يختفي التعديل من التخزين تلقائيًا.

**ملاحظة لمن يدير الموقع:** الأسابيع المتاحة في نافذة التخصيص هي الأسابيع الموجودة في ملف الجدول؛ لإضافة أسبوع جديد للجميع أضفه في الملف كما في القسم 4. أيام الدوام المعروضة في حقل "اليوم" تُضبط من `workDays` في `data/university.json`:

```json
"workDays": ["Sunday", "Monday", "Tuesday", "Wednesday", "Thursday"]
```

## 7) الإجازات وتتبّع الدرجات

**مزامنة الإجازات مع الجدول:** أضف نطاق أي إجازة إلى `data/calendar.json` تحت مفتاح `holidays` الخاص بالفصل:

```json
"holidays": [
  { "id": "s1-national-day", "startDate": "2026-09-23", "endDate": "2026-09-24", "labelAr": "إجازة اليوم الوطني", "labelEn": "National Day holiday" }
]
```

الموقع يقرأ هذا المفتاح وحده لتمييز الأيام والأسابيع: يوم إجازة داخل أسبوع عادي يظهر بشارة وخلفية مخططة، وأسبوع إجازة بالكامل يظهر ببانر واحد بدل تكرار بطاقات فارغة. لا حاجة لتعديل ملف الجدول نفسه؛ يكفي تعديل `calendar.json` وحده، وينعكس ذلك في كل مكان (الجدول، شريط تبويبات الأسابيع، التقويم).

**تتبّع أوزان التقييم:** أضف مصفوفة `assessments` إلى أي مادة في `data/subjects.json`:

```json
"assessments": [
  { "id": "quiz", "labelAr": "اختبار قصير", "labelEn": "Quiz", "weight": 5 },
  { "id": "final", "labelAr": "الاختبار النهائي", "labelEn": "Final Exam", "weight": 40 }
]
```

يظهر حينها زر 🎓 بجانب المادة في لوحة "إنجاز المواد"، يفتح نافذة لإدخال الدرجة المحصَّلة في كل بند، وتحسب النسبة الإجمالية حيًّا مع ما يلزم من الباقي لتحقيق هدف تختاره. الدرجات تُحفظ محليًا في هذا الجهاز فقط (المفتاح `kkuGrades`) ولا تُرسل لأي مكان ولا تُقرأ من أي ملف بيانات.

## 8) ملاحظات تقنية موجزة

- **لا يوجد بناء (build) ولا حزم npm** — HTML/CSS/JS خام يعمل من أي خادم ثابت، بما فيه GitHub Pages.
- **الحفظ محلي بالكامل**: اختيار السنة/التخصص/المجموعة يُحفظ في `localStorage` تحت المفتاح `kkuSelection`، وحالة "تمت المذاكرة" تحت `kkuLectureChecklist`، واللغة تحت `kkuLanguage`، والوضع الداكن/الفاتح تحت `kkuTheme`، والتخصيصات الشخصية تحت `kkuCustomizations`، والدرجات تحت `kkuGrades`. لا شيء يُرسَل لأي خادم.
- **"المتأخرات" (Backlog)** تُحتسب فقط للمحاضرات الأساسية (`isCoreLecture: true`) التي **انتهى وقتها فعليًا** ولم تُعلَّم كمكتملة — لا تُحتسب المحاضرات المستقبلية إطلاقًا.
- إذا ظهرت شاشة خطأ عند التشغيل، السبب شبه الأكيد أنك فتحت الملف مباشرة بدل تشغيل خادم محلي (راجع القسم 1).
